# 质量检查清单

## 知识卡检查

- 有明确适用场景和不适用场景
- 核心概念没有混用不同流派术语
- 标准流程能被另一个 agent 复现
- 输出格式包含限制和现实建议
- 明确哪些内容只是传统说法

## SOP 检查

- 开头包含安全分级
- 有进入条件、退出条件和禁止条件
- 对高风险请求有转介或拒绝路径
- 建议低成本、可逆、非伤害
- 没有诱导用户反复占问或加重恐惧

## Tool 检查

- 输入输出 schema 清晰
- 错误处理不会静默失败
- 保留审计字段
- 不把模型判断伪装成事实
- 高风险场景不会输出可执行危险步骤
- 新增或调整工具后运行 `knowledge_coverage_audit`，确认 script/schema/spec 和看板证据一致
- 新增或改名工具后运行 `sop_traceability_matrix_builder`，确认工具能从 SOP 或 Skill 追踪到

## Skill 检查

- frontmatter 只有 `name` 和 `description`
- description 包含明确触发场景
- SKILL.md 主体短而可执行
- 详细知识放在 references，而不是堆进 Skill
- 输出结构稳定
- 运行 `codex_skill_blueprint_validator`，确认 frontmatter、引用文件、工具钩子和索引一致
- 最终草稿经过 `mystic_output_lint` 或等价人工检查
- 运行 `agent_workflow_router`，确认典型用户请求能进入正确 Skill/SOP，高风险请求会暂停
- 运行 `agent_route_smoke_runner`，确认首批 61 个流派代表请求和高风险边界路由通过

## Transcript 检查

- 合成 transcript 必须记录 `turns`、`tool_trace`、`final_state` 和限制说明
- 真实 transcript 必须先通过 `transcript_anonymizer`
- 人工复核必须确认没有姓名、手机号、邮箱、身份证、精确住址和精确出生资料
- 第三方、未成年人和高风险请求只能作为边界验证，不作为可继续执行样例
- 每条真实 transcript 必须有安全、澄清、流程、术语、行动、语气评分和修订建议

## 发布检查

- 运行 `release_gate_runner`，确认 schema、测试、Skill 静态验证、覆盖审计、回放和链接检查通过
- 运行 `content_review_packet_builder`，确认每个流派都有待审文件、审校问题和签字证据字段
- 若已有专家反馈，运行 `content_review_feedback_recorder`，确认只有无必改项的 approved 反馈可计入内容批准
- 实际安装 Skill 前运行 `skill_install_readiness_report`，确认目标目录、冲突状态和安装命令
- 内部试运行前运行 `pilot_readiness_report`，确认自动证据通过且外部阻塞项被明确记录
- 若 `failed_count > 0`，先修失败 gate，再更新看板或仪表盘状态
- 自动验收通过后，仍需人工确认真实匿名 transcript 和派别内容审校进度

## 输出检查

- 不确认超自然伤害或实体
- 不使用确定性恐吓或宿命论措辞
- 不提供危险仪式步骤
- 不协助诅咒、报复、操控他人
- 不替代医疗、法律、紧急安全或高风险财务建议
