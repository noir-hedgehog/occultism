# 内容审校反馈记录规范

## 用途

本规范说明如何把内容专家对 [内容审校包](内容审校包.md) 的反馈记录成结构化证据。

`content_review_packet_builder` 负责准备待审材料；`content_review_feedback_recorder` 负责记录审校结果。两者都不替代真实审校人。

## 可计入批准的条件

| 条件 | 要求 |
| --- | --- |
| 流派 | 必须是覆盖审计中的 61 个流派之一 |
| 审校人 | 必须填写 `reviewer` |
| 日期 | 必须填写 ISO 日期，例如 `2026-07-02` |
| 决策 | 必须是 `decision: approved` |
| 批准范围 | 必须填写至少一项 `approved_scope` |
| 必改项 | `required_corrections` 必须为空 |

只有以上条件同时满足，`can_count_as_content_approval` 才能为 `true`。

## 修改请求

若审校结论是 `changes_requested` 或 `rejected`，必须填写 `required_corrections`。工具会生成 `kanban_updates`，维护者应把这些条目转入看板 Doing 或 Backlog。

## 命令

批准样例：

```bash
python3 agent-tools/scripts/content_review_feedback_recorder.py --domain tarot --reviewer "tarot-reviewer" --review-date 2026-07-02 --decision approved --approved-scope "塔罗 SOP、知识卡、Skill 和工具 spec"
```

要求修改样例：

```bash
python3 agent-tools/scripts/content_review_feedback_recorder.py --domain fengshui --reviewer "fengshui-reviewer" --review-date 2026-07-02 --decision changes_requested --approved-scope "风水 SOP 初审" --required-correction "补充玄空飞星字段不足时的拒绝样例"
```

## 限制

- 该工具记录反馈，不判断审校人的资质。
- 该工具不自动更新版本记录或看板；维护者必须复核后手动更新。
- 真实匿名 transcript、实际 Skill 安装和专家内容批准仍是独立发布条件。
