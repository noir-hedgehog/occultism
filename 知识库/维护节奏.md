# 维护节奏

## 每次变更

- 更新对应 SOP、知识卡、Skill、工具 spec/schema 和测试。
- 运行 `agent_workflow_router`，确认典型请求路由仍正确。
- 运行 `agent_route_smoke_runner`，确认 61 个流派代表请求仍可路由。
- 运行 `agent_runtime_dry_run_runner`，确认代表请求满足 runtime 工具契约。
- 运行 `agent_tool_wrapper_manifest_builder`，确认脚本、schema、流派、Skill 和安全标签可包装。
- 运行 `agent_tool_definition_exporter`，确认 agent tool definitions 可导出。
- 运行 `agent_tool_definition_validator`，确认 agent tool definitions 可注册。
- 运行 `agent_tool_registry_builder`，确认工具注册顺序和安全启动工具没有漂移。
- 运行 `agent_tool_registry_validator`，确认注册表索引、Skill 必备工具和安全 bootstrap 没有漂移。
- 运行 `agent_runtime_handoff_builder`，确认运行时入口、工具链和安全不变量可交接。
- 运行 `sop_traceability_matrix_builder`，确认 SOP/Skill 与工具链仍可追踪。
- 运行 `pilot_readiness_report`，确认内部试运行状态与外部阻塞项。
- 运行 `external_evidence_intake_builder`，确认外部证据字段、命令模板和验收标准仍与阻塞项一致。
- 运行 `python3 agent-tools/scripts/release_gate_runner.py`。
- 用 `python3 agent-tools/scripts/release_manifest_builder.py --version <版本号>` 生成或更新版本记录。

## 每周或每批素材

- 处理真实匿名 transcript，使用 `transcript_anonymizer` 和 `transcript_fixture_builder`。
- 把失败评分回写到 SOP、Skill 或工具修订任务。
- 复查看板 Doing/Backlog 是否仍反映真实状态。

## 每月

- 抽查各流派边界和禁用表达。
- 扩展跨流派深度矩阵和案例库。
- 运行 `content_review_packet_builder`，把待审问题分配给对应审校人。
- 收到反馈后运行 `content_review_feedback_recorder`，把必改项转为看板任务。
- 确认稳定 Skill 是否需要安装、覆盖或下线。

## 发布前

1. 运行 `release_gate_runner`。
2. 运行 `knowledge_coverage_audit`。
3. 运行 `codex_skill_installer` dry-run。
4. 运行 `content_review_packet_builder`。
5. 若已有审校反馈，运行 `content_review_feedback_recorder`。
6. 若准备安装 Skill，运行 `skill_install_readiness_report`。
7. 运行 `external_evidence_intake_builder`，确认外部证据入口没有漂移。
8. 运行 `agent_runtime_dry_run_runner`，确认 runtime 契约没有漂移。
9. 运行 `agent_tool_wrapper_manifest_builder`，确认 wrapper 元数据没有漂移。
10. 运行 `agent_tool_definition_exporter`，确认工具定义导出没有漂移。
11. 运行 `agent_tool_definition_validator`，确认工具定义验证没有漂移。
12. 运行 `agent_tool_registry_builder`，确认工具注册表没有漂移。
13. 运行 `agent_tool_registry_validator`，确认工具注册表验证没有漂移。
14. 运行 `agent_runtime_handoff_builder`，确认 runtime dry-run 交接包没有漂移。
15. 生成 release manifest。
16. 人工复核真实匿名 transcript、实际 Skill 安装和内容审校进度。
