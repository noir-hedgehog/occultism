## 维护规则

- 每次新增工具、Skill 或知识卡后，重新运行 `release_gate_runner`。
- 新增或改名工具后，运行 `sop_traceability_matrix_builder` 检查流程追踪。
- 修改 intake、Skill 或流派映射后，运行 `agent_workflow_router` 检查运行时路由。
- 修改 intake、路由别名或 Skill 映射后，运行 `agent_route_smoke_runner` 做批量冒烟验证。
- 接入或调整 runtime wrapper 前，运行 `agent_runtime_dry_run_runner` 验证工具契约。
- 生成 MCP/API wrapper 前，运行 `agent_tool_wrapper_manifest_builder` 复核 wrapper 元数据。
- 注册 agent tools 前，运行 `agent_tool_definition_exporter` 复核工具定义和 OpenAI-style function tool。
- 注册 agent tools 前，运行 `agent_tool_definition_validator` 复核定义形状、本地引用和安全标签。
- 注册 agent tools 前，运行 `agent_tool_registry_builder` 复核注册顺序和安全启动工具。
- 注册 agent tools 前，运行 `agent_tool_registry_validator` 复核注册表索引、Skill 必备工具和安全 bootstrap。
- 接入 agent runtime 前，运行 `agent_runtime_handoff_builder` 生成交接包并复核安全不变量。
- 内部试运行前，运行 `pilot_readiness_report` 复核自动证据和外部阻塞项。
- 外部证据进入收集阶段前，运行 `external_evidence_intake_builder` 生成安装确认、真实 transcript 和内容审校入口。
- 大批量调整知识库结构后，用 `knowledge_navigation_builder` 刷新导航索引。
- 内容发布前，用 `content_review_packet_builder` 生成审校包并记录专家反馈。
- 收到专家反馈后，用 `content_review_feedback_recorder` 判断是否可计入内容批准。
- 实际安装前，用 `skill_install_readiness_report` 复核目标路径、冲突和审批清单。
- 发布前用 `release_manifest_builder` 生成最新 manifest，并复核开放事项。
- 接 agent runtime、MCP 或 API wrapper 前，用 `tool_manifest_builder` 生成工具/Skill manifest。
- 版本记录只能引用当前自动证据，不手工夸大完成度。
