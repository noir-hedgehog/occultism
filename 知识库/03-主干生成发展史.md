# 主干生成发展史

本页解释 6 条主干是怎么从早期流派清单生成出来的。它不是玄学史通论，而是本项目的信息架构发展史：为什么这些内容应该归在一起，为什么后续不再轻易新增碎片分支。

## 阶段一：安全骨架先行

最早的主干不是某个流派，而是安全边界：

- 用户可能会把占卜、命理、驱邪、仪式、身体征兆和重大决策混在一起提问。
- agent 必须先区分低风险象征反思、专业替代风险、即时安全风险和危险仪式。
- 因此 `mystic_intake_triage`、`ritual_safety_check`、`mystic_output_lint` 先于流派解释存在。

这一步生成了后续所有流派共享的底层约束：不做医疗、法律、财务替代；不做恐吓；不确认灵体事实；不承诺结果；不鼓励危险仪式。

## 阶段二：从代表流派到可执行链

第二阶段先选择高频且边界差异明显的代表场景：

- 塔罗：牌阵、牌义、正逆位、组合解释。
- 风水：空间观察、动线、采光、收纳和安全。
- 易经/周易：起卦、卦爻、原典来源和重复占问。
- 奇门、六爻、梅花、命理：盘式、用神、派别和出生资料边界。
- 空间净化/驱邪：危险仪式降级为低风险文化/整理流程。

这个阶段的关键不是“懂更多名词”，而是形成 `知识卡 -> SOP -> Tool -> Skill -> 回放验证` 的链条。

## 阶段三：扩展到 61 个领域

第三阶段吸收更多真实会出现的请求类型，包括牌卡、签文、符物、香火、水晶、身体征兆、通灵、前世、月相、民俗、招财、桃花、开光、失物等。

扩展过程中出现一个风险：流派越分越细，容易忽略真正的主干能力。因此项目把 61 个领域重新归并为 6 条主干：

1. 占问与决策框架。
2. 随机媒介与符号读取。
3. 空间、环境与居住体验。
4. 仪式、象征物与护持叙事。
5. 身体、睡眠、梦境与心理叙事。
6. 民俗、时令与征兆。

这 6 条不是学术分类，而是 agent 执行分类：每条主干都有相似的输入、风险、工具链和输出方式。

## 阶段四：从流派路由到范式选择

单纯识别流派还不够。同一句“帮我看塔罗”可能是：

- 情绪梳理。
- 两个选择的对照。
- 对未来的确定预测。
- 财务、医疗或关系操控风险。
- 想学习塔罗来源和牌义。

所以当前阶段新增“问题到范式”层：先判断用户具体问题要用哪种处理范式，再决定自动化和 agent 的分工。

主要范式包括：

- 安全/专业边界暂停。
- 来源语境与勘误。
- 现实观察与低风险行动。
- 身体/睡眠体验记录。
- 媒介记录与象征反思。
- 问题澄清与决策镜像。
- 民俗语境与安全回应。
- 低风险象征反思。

## 阶段五：人机交互与程序化运行

当前目标是把知识库和工具链变成可使用的工作台：

- 人看的部分：知识库文档站、主干发展史、问题到范式映射、看板和仪表盘。
- 程序化部分：intake、route、paradigm selection、manifest、registry、dry-run、lint。
- 需要 agent 的部分：读取 SOP 和知识卡、综合工具输出、形成解释、追问上下文、写出安全自然语言回应。
- 需要人工/专家的部分：派别来源审校、真实匿名案例评分、强神秘内容边界复核。

## 后续原则

以后新增内容优先问三个问题：

1. 这是新主干，还是已有主干的一个案例？
2. 这是新工具，还是现有范式的一项字段？
3. 它能被来源、案例或运行时证据验证吗？

答不上来时，不新增 Skill，只补知识卡、别名、案例或安全反例。
