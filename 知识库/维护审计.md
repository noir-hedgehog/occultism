# 维护审计

## 用途

本页说明如何用 `knowledge_coverage_audit` 检查知识库、工具、Skill、看板和仪表盘是否保持一致。它是维护者进入项目后的体检入口。

## 运行方式

```bash
python3 agent-tools/scripts/knowledge_coverage_audit.py
```

## 审计范围

| 范围 | 检查内容 |
| --- | --- |
| 流派覆盖 | 每个首批流派是否有 SOP、知识卡、Skill、工具链和验证证据 |
| 通用知识库 | README、总览、安全边界、流派地图、质量清单、路线图、看板、仪表盘 |
| 模板 | Tool、SOP、流派知识卡、Codex Skill 模板 |
| 通用工具 | intake、output lint、深度矩阵、案例库、真实 transcript 脱敏 |
| 验证资产 | 单元测试、人工样例、Skill 回放、多轮回放、匿名真实对话流程 |
| Skill 蓝图 | frontmatter、引用文件、工具钩子和索引依赖 |
| Agent 路由 | 用户请求到流派、Skill、SOP、知识卡和初始工具链的运行计划 |
| 路由冒烟验证 | 61 个流派代表请求和高风险暂停/阻断路径 |
| Agent 运行时 dry-run | ready 路径与 paused/blocked 路径的 runtime 工具契约 |
| Agent 工具 wrapper manifest | 脚本命令、输入 schema、关联 Skill、流派和安全标签 |
| Agent 工具定义导出 | agent tool definition 和 OpenAI-style function tool 形状 |
| Agent 工具定义验证 | 注册前工具定义、OpenAI-style function tool 和本地引用检查 |
| Agent 工具注册表 | runtime 注册顺序、流派/Skill 索引和安全启动工具 |
| Agent 运行时交接 | runtime 入口、Skill、工具 manifest、安全不变量和验证命令 |
| 工具/Skill manifest | 工具三件套、Skill 依赖和 agent runtime 清单 |
| 导航索引 | 维护者入口、流派入口、SOP 列表、工具与验证链接 |
| 内容审校 | 每个流派的待审文件、工具链、审校问题、签字证据和开放项 |
| 审校反馈 | 审校人、日期、批准范围、必改项、残余风险和看板更新建议 |
| Skill 安装准备 | dry-run 行动、目标目录、冲突状态、审批清单和安装命令 |
| SOP 追踪矩阵 | SOP、知识卡、Skill、工具链和验证证据之间的引用关系 |
| 试运行准备 | 自动证据、内部试运行状态、完整发布状态和外部阻塞项 |
| 外部证据入口 | 安装确认、真实 transcript 和专家审校的字段、命令模板与验收标准 |
| 版本维护 | 版本记录、维护节奏和 release manifest |

## 解读方式

- `is_valid: true`：关键文件覆盖齐全，可以继续跑质量门。
- `domains[].missing`：某个流派缺少的文件或工具三件套。
- `common.missing`：项目级导航、模板或验证资产缺口。
- `limits`：提醒覆盖齐全不等于内容穷尽。
- 发布前运行 [发布验收](发布验收.md) 中的 `release_gate_runner`。

## 维护规则

- 新增流派时，先补 SOP、知识卡和 Skill，再补工具三件套。
- 新增流派或修改 intake 规则后，运行 `agent_workflow_router` 验证请求能路由到正确 Skill/SOP。
- 修改 intake、路由别名或 Skill 映射后，运行 `agent_route_smoke_runner`。
- 接入或调整 runtime wrapper 前，运行 `agent_runtime_dry_run_runner` 验证 ready/paused/blocked 工具契约。
- 生成 MCP/API wrapper 前，运行 `agent_tool_wrapper_manifest_builder` 确认每个脚本都有命令、schema 和安全标签。
- 注册 agent tools 前，运行 `agent_tool_definition_exporter` 确认 definitions 和 OpenAI-style function tools 可导出。
- 注册 agent tools 前，运行 `agent_tool_definition_validator` 检查定义形状和本地引用。
- 注册 agent tools 前，运行 `agent_tool_registry_builder` 生成注册顺序和安全启动工具。
- 注册 agent tools 前，运行 `agent_tool_registry_validator` 检查注册表索引、命令、安全标签和 bootstrap 一致性。
- 接入 agent runtime 前，运行 `agent_runtime_handoff_builder` 确认入口、工具链和安全不变量。
- 新增工具时，必须同时补 script、schema、spec、测试和工具目录。
- 大批量新增知识卡或 SOP 后，运行 `knowledge_navigation_builder` 更新导航索引。
- 新增或改名工具后，运行 `sop_traceability_matrix_builder` 确认 SOP/Skill 引用没有漂移。
- 发布前用 `content_review_packet_builder` 生成审校包，并记录未批准项。
- 收到审校意见后，用 `content_review_feedback_recorder` 记录能否计入内容批准。
- 仪表盘的 L3 状态应能被覆盖度审计和质量门共同支持。
- 迁移 Skill 前必须运行 `codex_skill_blueprint_validator`。
- 接 MCP/API wrapper 前必须运行 `tool_manifest_builder`。
- 实际安装 Skill 前必须先运行 `skill_install_readiness_report` 并获得用户明确确认。
- 进入内部试运行前运行 `pilot_readiness_report`，确认自动证据和外部阻塞项。
- 开始收集真实安装、真实 transcript 或专家审校前运行 `external_evidence_intake_builder`，确认字段和验收标准一致。
- 发布前必须运行 `release_gate_runner`。
- 发布记录必须用 `release_manifest_builder` 汇总当前自动证据。
- 真实匿名 transcript 进入回放前，仍需 [匿名真实对话验证流程](匿名真实对话验证流程.md)。
